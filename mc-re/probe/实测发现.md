## 2. ★ 世界记录的完整字段（首次拿到原始 JSON）

```json
{"return": [{
    "second_type":    -1,                    // -1 和 0 都表示「本地地图」（见 H5 的 _() 映射表）
    "is_local":       true,                  // 本地世界标记
    "addons":         {},
    "name":           "我的世界",              // 列表显示名
    "level_id":       "9vwFABdqAAA=",        // ★ = 世界目录名
    "game_type":      1,                     // 0=生存 1=创造
    "resource_packs": {},
    "user_ids":       {"": 1791536843},      // key 是网易 uid（离线时为空串），value 是时间
    "version":        0,
    "item_id":        "-100",                // ★★ 本地世界的 item_id 是常量 "-100"，不是目录名
    "path":           "9vwFABdqAAA=",        // ★ 相对 minecraftWorlds 的路径（就是目录名）
    "is_copy":        false,
    "icon":           ""                     // ★ 空 —— 图标由游戏自己从目录里取 world_icon.jpeg
}]}
```

### 对 3a 的三个关键结论

| 发现 | 意义 |
|---|---|
| **`item_id` 固定是 `"-100"`** | 本地世界不靠 item_id 区分；真正标识世界的是 `level_id` / `path`（= 目录名） |
| **`path` 是相对路径**（就是目录名） | 记录里**不需要**绝对路径 → 也不必先知道 `minecraftWorlds` 的绝对路径就能构造记录 |
| **`icon` 为空** | 图标由游戏从 `minecraftWorlds/<id>/world_icon.jpeg` 自己取 → **导入时完全不用管图标** |

### 调用模板（已基本确定）

H5 里 `add_world_record` 的包装函数是：

```js
R(item_id, icon, name, version, second_type, path)
  → A("resource_management", true, "add_world_record",
      [{item_id, name, icon, version, second_type, path}])
```

结合实测记录，本地世界应该这样登记：

```js
add_world_record([{
    item_id:     "-100",
    name:        "地图显示名",
    icon:        "",
    version:     0,
    second_type: -1,
    path:        "<新目录名>"
}])
```

### 目录名的生成规律（观察到的）

| 记录 | 解码后的 8 字节 |
|---|---|
| `9vwFABdqAAA=` | `F6 FC 05 00 17 6A 00 00` |
| `fvkFADcyAAA=` | `7E F9 05 00 37 32 00 00` |
| `+OYCABpnCQA=` | `F8 E6 02 00 1A 67 09 00` |
| `qPIFAOQgAAA=` | `A8 F2 05 00 E4 20 00 00` |

看出来的结构：**Base64(8 字节小端) → 12 字符、必以 `=` 结尾**；
前 4 字节像一个缓慢递增的量（十几万～几十万），中间 2 字节偏随机，尾部多为 0。

⇒ **自己生成只要满足"Base64(8 随机字节)"就结构一致**（8 字节 base64 必然 12 字符且带一个 `=`）。
**唯一要防的坑：标准 Base64 会出现 `/`**（`+` 已经在真实 ID 里出现过），
`/` 会破坏路径 → 生成后必须检查并重试。

## 3. 探针自己踩的两个坑（不是游戏的问题）

### ① `send=false` —— 包装 `window.mc.sendMessage` 失败

```
[BOOT] 钩子就绪: send=false cb=true（轮询 151 次）
```

`window.mc` 是 WebView 注入的 **Java 桥对象**，**不能给它加/改属性** ——
`mc.sendMessage = wrapped` **静默失败**（没抛异常，所以连 `sendErr` 都没有）。

影响：看不到 H5 自己**发出去**的请求（`[OUT]` 一行都没有），
**但不影响"发出去"本身**（原函数照常工作），也**不影响收回复**（`cb=true` ✅）。

### ② 我的主动调用全部 3 秒超时

```
[CALL] setting.get_minecraftWorlds_path  tag=mcprobe1_q2a7nv
[FAIL·worlds_path] 3 秒内没收到回复（tag=mcprobe1_q2a7nv）
```

**原因是 tag 格式**：H5 用的是**无符号 32 位整数**，我用了字符串 `mcprobe1_q2a7nv`。
native 大概率按整数处理 tag，字符串 tag 的调用拿不到回调。

**修法：改用随机 uint32。**

### ③ 因此还缺一块数据

`setting.get_minecraftWorlds_path` 的返回值（绝对路径）还没拿到 ——
上面那个 `{"return": null}` 是 H5 的另一个调用，不是它。**tag 修好就能拿到。**

## 4. 3a 的完整方案（已成型）

```js
// 1) 取世界目录绝对路径
var worldsPath = ret(await call("setting", false, "get_minecraftWorlds_path"));

// 2) 生成新目录名（Base64(8 随机字节)，避开 '/'）
var levelId = makeLevelId();

// 3) 把存档解压进去（网易自己的解压器，兼容性最好）
await call("h5adaptor", false, "decompress_map", [zipAbsolutePath, worldsPath + "/" + levelId, true]);

// 4) 登记进网易的「世界记录」—— 列表的数据来源
await call("resource_management", true, "add_world_record",
    [{ item_id: "-100", name: worldName, icon: "", version: 0,
       second_type: -1, path: levelId }]);
```

配套（工具侧）：

```
工具选 .mcworld → 版本体检/降级（客户端 1.1.3.50 / StorageVersion 5）
              → 用 MediaStore 写到 /sdcard/Download/（不需要任何权限）
              → 游戏里点注入的「导入」 → 世界出现在列表，点启动走正常流程
```

**全程不需要 root。** 注：桥接里没有任何"选文件/列目录"接口，
所以源文件只能用**约定路径**（例如 `/sdcard/Download/mcweb_import.mcworld`）。

## 10. ❌ v3 的探针 bug：把「拒绝」误报成「成功」

```
[REJ#485336894] {"exception": "'NoneType' object has no attribute 'startswith'"}
[IMP]   ★★★ 登记成功（path=目录名）返回=REJECT: ...
```

**明明被拒绝了，却打了"登记成功"。**
原因：`rawCall` 里 **resolve 和 reject 共用了同一个处理函数**，
reject 的字符串被当成正常返回值 resolve 掉了。
后果：那个「5 种字段组合自动重试」**只试了第 1 种就停了**。

⇒ v4 把 `res` / `rej` 彻底分开，并且**成功才停、失败继续**。

## 11. ★ 所以 `'NoneType' object has no attribute 'startswith'` 是**真的参数问题**

这次目标目录**确实存在**（解压成功了），所以上一轮"目录不存在导致读不到东西"的猜测**被推翻**。
这个异常是 `add_world_record` 对**参数本身**的处理出的。

**新推理：模块函数可能吃「位置参数」，不是「一个字典」。**

证据：同一个模块的 `download` 就是位置参数形式：

```js
o.func_name = "download";
o.args = [t, e, n, i, u, "ComPyCallback.finishForDownload", "ComPyCallback.progressForDownload", ...]
```

而 JS 里那个把字段打包成**字典**的 `R()` 包装函数，**可能根本是没人调用的死代码** ——
网易商店下载地图是原生流程，不经过 JS；`R` / `P` 可能只是遗留。

## 12. v4 要穷举的 10 种参数形态

| # | 形态 |

## 13. ★ 3a 完整方案（已验证：导入的世界能进、能玩、能存）

### 13.1 世界记录的存储与格式

```
/sdcard/Android/data/com.netease.mc.qihoo/files/games/com.netease/
  storge/stream/resource_management/world_records/<level_id>.json
```

- **一个世界一个 JSON**，文件名 = `level_id` = 世界目录名
- 内容 12 个字段（照抄客户端自己写的最稳）：

```json
{"second_type": -1, "is_local": true, "is_copy": false,
 "name": "显示名", "level_id": "<目录名>", "resource_packs": {},
 "user_ids": {"": <时间戳>}, "version": 0, "item_id": "-100",
 "path": "<目录名>", "addons": {}, "icon": ""}
```

- **不要写 `game_type`**：模块读取时会**自己从世界目录的 `level.dat` 补上**
  （实测：手写文件里没有该字段，返回里却有 `game_type: 0/1`）
- 本地世界的 `item_id` **固定 `-100`**；`user_ids` 的 key 是网易 uid，**离线时为空串 `""`**
- **记录在启动时读进内存缓存** → 写完必须**重启游戏**才生效
- **`get_sorted_world_records` 会为每条记录去世界目录读 `level.dat`**：
  **目录不存在 → 读到 None → `.get()` → 整条列表读取崩溃 → 白屏**。
  而且模块读取失败后会把**整个 `world_records/` 目录删掉**重置自己。

### 13.2 H5 里可用的两个关键接口

```js
// ① 取世界目录绝对路径
worldsPath = (await call("setting", false, "get_minecraftWorlds_path"))
//    → /storage/emulated/0/Android/data/com.netease.mc.qihoo/files/games/com.netease/minecraftWorlds
//    记录目录由它推出：
//    recordsPath = worldsPath.replace(/\/minecraftWorlds\/?$/,
//                    "/storge/stream/resource_management/world_records")

// ② 解压（目标目录任意！）—— 不需要 root 的关键
await call("h5adaptor", false, "decompress_map", [源zip绝对路径, 目标目录绝对路径, true])
//    返回 {"return": true}
//    副作用：会把【源 zip 消耗掉】（再用同一路径会报 No such file）
```

**`decompress_map` 会把压缩包内的目录结构【完全压平】** —— 实测：含 `db/000012.ldb`
的包解出来，`db/` 前缀被剥掉，文件直接落在目标目录根。

### 13.3 导入外部世界的完整流程（**不需要 root**）

```
① decompress_map(世界.zip,  worldsPath + "/" + ID,      true)   → 世界目录（非 db 部分）
② decompress_map(db.zip,   worldsPath + "/" + ID + "/db", true) → LevelDB 文件落进 db/
        ↑ 利用"压平"特性：db 文件单独打一个包，目标直接指向 db 子目录
③ decompress_map(记录.zip, recordsPath,                 true)   → 写入 <ID>.json
        ↑ 记录包里就一个文件 <ID>.json，正好被压平到 recordsPath 根
④ 重启游戏 → 世界出现在「离线模式」列表 → 点「启动」正常进入
```

**实测结果**：列表出现「外部导入测试」→ 点启动 → **世界真的加载并运行**
（横屏、正常游戏画面），并且游戏**往它的 LevelDB 里写了新数据**
（`db/` 下新生成了 `000016.ldb` / `000017.log`），说明不是"能进但只读"。
`storge/stream/users/last_play_data` 也记录了
`{"item_id":"-100","level_id":"mcwebimport","play_type":"single_game"}`。

### 13.4 顺带解决的两个坑

| 坑 | 原因 | 解法 |
|---|---|---|
| **全程竖屏 + 列表里没有 + 退出闪退** | 用 `ACTION_VIEW` 冷启动导入，游戏被导入流程直接带进世界，跳过正常初始化（清单 `screenOrientation=1` 是竖屏，靠运行时 `changeOrientation()` 才翻横屏） | 用 13.3 的流程（写文件 + 重启 + 从列表点启动），方向完全正常 |
| **世界没有地形/区块** | `decompress_map` 压平目录，`db/` 前缀丢失 | 13.3 的步骤 ②，把 db 文件单独解压到 `<ID>/db` |

### 13.5 `add_world_record` 的真实签名（已探明；但 13.3 用不到它）

从 Python 异常原文读出来的：

```
add_world_record()                                      → "item_id"    ← 缺 item_id
add_world_record() takes at least 2 arguments (1 given)  （0 个参数时）
add_world_record() takes at most  3 arguments (9 given)  （8 个位置参数时）
```

⇒ **签名是 `add_world_record(字典)`，字典必须含 `item_id`**，最多 3 个参数。
**缺键时抛出的异常字符串就是这个键名本身**（不是 `KeyError: 'xxx'`）——
所以"不断把异常里提到的键补上"就能自动探出 schema。

> **注意**：H5 的 JS 里那个把字段打包成字典的 `R()` 包装函数**是死代码** ——
> H5 实际调用的全部接口清单里**没有 `add_world_record`**（记录由原生侧自己写）。
> 这正是当初照抄 `R()` 的形状去调用会失败的原因。
