# 网易版 H5 桥接接口表（2026-10-10 实测）

从 `assets/web/*.js` 里抓出的**全部桥接调用**（63 组 module/func），
再在真机上用探针逐一验证过一部分。

## 调用格式

H5 里统一走一个 helper（压缩后名字是 `A`），底层就是 `window.mc.sendMessage`：

```js
// 抓到的源码形态
A("setting", !1, "get_minecraftWorlds_path")
A("h5adaptor", !1, "decompress_map", [zip, dest, true])
S.$utility.sendMessageToPython("resource_management", !1, "init_skin_list", [skins])
```

对应到桥接消息：

```json
{ "module_name": "setting", "func_name": "get_raw_skins_path",
  "use_instance": false, "args": [], "tag": 123456,
  "return_callback": "ComPyCallback.resolve",
  "exception_callback": "ComPyCallback.reject" }
```

> ⚠️ **`use_instance` 的坑（真机踩过）**：压缩 JS 里 **`!1` 是 `false`、`!0` 是 `true`**。
> 我一开始把 `!1` 当成"1 = true"，结果 `setting.*` 全部报
> `Can not find get_raw_skins_path in setting`。改成 `false` 后立刻正常。
> **⇒ 下面表里写的 `!1` 一律等于 `use_instance: false`。**

回调必须用官方写法（覆盖 `ComPyCallback.resolve` 收不到）：

```js
var tag = window.ComPyCallback.addToTagData([onOk, onErr]);
```

## 已验证可用的

| 调用 | 结果 |
|---|---|
| `setting.get_minecraftWorlds_path` (noInst) | ✅ `/storage/emulated/0/Android/data/com.netease.mc.qihoo/files/games/com.netease/minecraftWorlds` |
| `setting.get_resource_packs_path` (noInst) | ✅ `.../files/games/com.netease/resource_packs` |
| `setting.get_raw_skins_path` (noInst) | ✅ `.../files/games/com.netease/skin_packs` |
| `resource_management.init_skin_list([x])` (noInst) | ✅ 能调用（返回 null），但**参数是服务器下发的皮肤列表** —— 离线时 H5 自己的皮肤界面就卡在这（旁边就是"网络超时"提示） |
| `h5adaptor.decompress_map(源zip, 目标目录, true)` (noInst) | ✅ 以**游戏身份**往任意目录写文件；会**压平目录结构**；成功后会**消耗掉源 zip** |
| `resource_management.add_world_record({...})` (noInst) | ✅ 写世界记录（世界导入用的就是它） |

## 由此得到的两个可能收获

1. **不用重打 APK 就能换皮肤**：`decompress_map` 往 `skin_packs/` 写图，
   再想办法让游戏认它（`init_skin_list` 的参数格式还没搞清 —— 它平时吃的是服务器下发的列表）。
2. **★ 不用 root 就能换手臂粗细**：`options.txt` 在游戏自己的目录里
   （`/data/data/com.netease.mc.qihoo/games/com.netease/minecraftpe/options.txt`），
   **游戏自己能写**，所以 H5 也能整份覆盖它 ——
   代价是**其他设置（画质/控制）会回到默认**，因为 H5 没有"读文本文件"的接口，
   没法做只改一行的外科手术。
